# Trae Solo CN Vibe-Coding 规则

## 项目上下文

- **IDE：** Trae Solo CN
- **模式：** 快速 Vibe-Coding 工作流
- **目标：** 从明确需求到 MVP 的高效开发

## 核心原则

1. **跳过市场调研** — 用户已有明确需求
2. **直奔主题** — 需求 → PRD → 技术设计 → 构建
3. **保持简洁** — 不要过度文档化，快速进入开发

## 工作流程

```
💡 需求 ──► 📋 PRD ──► 🏗️ 技术设计 ──► 🤖 Agent配置 ──► 🚀 构建
```

### 阶段1：需求确认（5分钟）
- 用户描述核心功能
- AI 整理并确认理解
- 只问必要问题（不超过4个）

### 阶段2：PRD 生成（5分钟）
- 功能列表（只分 P0/P1）
- MVP 边界
- 快速生成文档

### 阶段3：技术设计（5分钟）
- 推荐技术栈（如果用户没指定）
- 确定项目结构
- 核心组件设计

### 阶段4：Agent 配置（1分钟）
- 从 `templates/` 复制文件
- 填充占位符
- 立即开始构建

### 阶段5：构建循环
- 计划 → 执行 → 验证
- 一次一个功能
- 频繁确认

## 文档优先级

1. `START.md` — 总入口
2. `AGENTS.md` — 当前任务
3. `agent_docs/` — 必要的技术细节

## 禁止事项

- ❌ 不要做市场调研或竞品分析
- ❌ 不要生成冗长的研究文档
- ❌ 不要问超过4个问题
- ❌ 不要过度设计
- ❌ 不得添加 MVP 范围外的功能

## 必须事项

- ✅ 直接询问核心功能需求
- ✅ 快速生成 PRD 和技术设计
- ✅ 立即开始构建
- ✅ 频繁验证和确认
- ✅ MVP 优先，简化方案

## 模型使用建议

- 简单任务：使用 豆包
- 复杂架构：使用 DeepSeek
- 代码生成：使用 豆包

## 快速开始命令

```
@agent 读取 START.md，我已经有明确的需求，直接开始
```
