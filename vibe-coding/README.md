# Vibe-Coding 工作流

> 一个简洁高效的 AI 辅助开发工作流，适用于 Trae Solo CN。

## 快速开始

### 1. 复制文件到你的项目

将 `vibe-coding/` 文件夹复制到你的项目根目录：

```
your-project/
├── vibe-coding/     ← 复制这个文件夹
├── src/             ← 你的代码
└── package.json
```

### 2. 开始项目

在 Trae 中对 AI 说：

```
@agent 读取 vibe-coding/START.md，我已经有明确的需求，直接开始
```

### 3. AI 执行以下操作

1. 询问4个问题确认需求
2. 生成 `docs/PRD-*-MVP.md`
3. 生成 `docs/TechDesign-*-MVP.md`
4. 从 `templates/` 复制配置文件到项目根目录
5. 开始构建

## 项目结构

```
vibe-coding/
├── START.md                    # 工作流入口
├── .trae/rules/                # Trae 规则
│   └── vibe-coding.md
├── templates/                  # Agent 配置模板
│   ├── AGENTS.md              # 主配置文件
│   ├── MEMORY.md              # 会话记忆
│   └── REVIEW-CHECKLIST.md    # 审查清单
└── agent_docs/                 # Agent 知识库
    ├── product_requirements.md # 产品需求
    ├── tech_stack.md          # 技术栈
    ├── code_patterns.md       # 代码规范
    └── testing.md             # 测试策略
```

## 生成的配置文件

AI 执行后会自动生成以下文件到你的项目根目录：

```
your-project/
├── docs/                       # 规划文档
│   ├── PRD-[项目名]-MVP.md
│   └── TechDesign-[项目名]-MVP.md
├── agent_docs/                 # Agent 知识库
│   ├── product_requirements.md
│   ├── tech_stack.md
│   ├── code_patterns.md
│   └── testing.md
├── AGENTS.md                  # 主配置
├── MEMORY.md                  # 进度记录
└── REVIEW-CHECKLIST.md        # 审查清单
```

## 工作流程

```
需求 → PRD → 技术设计 → Agent配置 → 构建
```

### 阶段说明

| 阶段 | 时间 | 说明 |
|------|------|------|
| 需求确认 | 5分钟 | 你描述功能，AI整理 |
| PRD生成 | 5分钟 | 明确功能范围和优先级 |
| 技术设计 | 5分钟 | 确定技术栈和架构 |
| Agent配置 | 1分钟 | 生成编码指令 |
| 构建 | 开始 | 计划→执行→验证循环 |

### AI 询问的问题

1. "请描述你的项目需求，包括核心功能"
2. "列出必须有的3个核心功能"
3. "你偏好什么技术栈？"
4. "你的项目有后端吗？"

## 命令参考

| 命令 | 说明 |
|------|------|
| "读取 START.md，直接开始" | 从需求开始完整流程 |
| "提议第一个功能的实现计划" | 开始构建阶段 |
| "显示当前进度" | 查看 MEMORY.md |
| "下一个功能是什么？" | 继续开发 |
| "运行测试" | 执行测试 |

---

## 故障排除

| 情况 | 命令 |
|------|------|
| AI 做多余调研 | "跳过调研，直接进入PRD" |
| 过于复杂 | "简化方案，MVP最简方式是什么？" |
| 不满意结果 | "调整[功能]，重新生成" |
| 进度不明 | "显示当前进度" |

---

## 核心原则

1. **跳过市场调研** — 用户已有明确需求
2. **直奔主题** — 需求 → PRD → 技术设计 → 构建
3. **保持简洁** — 不要过度文档化，快速进入开发
