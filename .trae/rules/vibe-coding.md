# Trae Solo CN Vibe-Coding 规则

## 项目上下文

- **IDE：** Trae Solo CN
- **模式：** 自动化 Vibe-Coding 工作流
- **目标：** 从想法到 MVP 的全流程开发

## 工作流程

1. 始终先读取 `START.md` 了解完整流程
2. 按顺序执行：研究 → PRD → 技术设计 → Agent配置 → 构建
3. 遵循 计划→执行→验证 循环

## 文档优先级

1. `START.md` — 总入口
2. `AGENTS.md` — 当前任务
3. `agent_docs/` — 技术细节
4. `docs/` — 规划文档

## 开发规范

### 编码规则
- 优先 MVP 范围，不要过度设计
- 一次实现一个功能
- 完成后立即测试
- 保持代码简洁

### 文件管理
- 将重要信息写入文件而非留在聊天中
- 使用 `MEMORY.md` 跟踪进度
- 每次功能完成后更新 MEMORY.md

### 沟通要求
- 简明扼要，不重复
- 不确定时先提问
- 编码前先提出计划并等待批准

## 禁止事项

- 未经确认不得删除文件
- 不得添加 MVP 范围外的功能
- 不得跳过测试
- 不得绕过失败的检查

## 模型使用建议

- 简单任务/快速迭代：使用 豆包
- 复杂架构/深度推理：使用 DeepSeek
- 代码生成：使用 豆包
- 研究分析：使用 DeepSeek
